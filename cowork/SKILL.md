# Reference Verification (Claude / Cowork)

업로드된 문서의 **참고문헌과 인용을 검증**하는 스킬. **남이(또는 AI가) 이미 써 놓은 인용이 맞는지**를 사후 검증하는 데 특화됐다.

> 이 변형은 **Claude 앱(Cowork)** 용이다. 코드 실행 샌드박스(Python)·웹 검색·파일 업로드/다운로드를 전제한다. Claude Code(CLI)에서는 `claude-code/SKILL.md`를 사용하라.

핵심 원칙: **출처가 존재한다 ≠ 그 출처가 본문 주장을 뒷받침한다.** 서지 실존만 보면 통과처럼 보이는 문서도, 인용 적절성을 따지면 과확장·변수 오기·자료원 불일치가 드러난다. 두 단계를 분리해 검증한다.

> 가장 비싼 실수는 "출처가 실재하니 OK"라고 끝내는 것이다. 실제 검증의 대부분은 2단계(인용 적절성)에서 일어난다.

## 실행 환경 준비 (Cowork)

- 사용자가 **검증할 문서를 채팅에 업로드**하면 샌드박스 작업 디렉터리에서 읽는다.
- PDF 판독·다운로드에 필요한 패키지는 샌드박스에서 설치한다: `pip install pymupdf requests`. (`poppler`/`pdftotext`는 없을 수 있으니 **PyMuPDF를 우선** 사용)
- 출처 검색·확인은 **웹 검색**으로 한다. 학습 지식만으로 답하지 않는다.
- 결과 리포트는 샌드박스에 파일로 만들어 **다운로드 링크로 제공**한다(.md 기본, 요청 시 .docx).

---

## 0단계: 인용 수집 (전수)

업로드된 문서에서 검증 대상 인용을 **빠짐없이** 추출한다.

```python
# docx 본문·각주·미주·하이퍼링크 전수 추출
import zipfile, re, html
z = zipfile.ZipFile('uploaded.docx')
for part in ['word/document.xml','word/footnotes.xml','word/endnotes.xml']:
    try:
        t = re.sub(r'<[^>]+>',' ', z.read(part).decode('utf-8'))
        print(part, html.unescape(re.sub(r'\s+',' ',t))[:3000])
    except KeyError:
        pass
print(z.read('word/_rels/document.xml.rels').decode('utf-8'))  # 하이퍼링크
```

- 내부 자료(기관 제공 PPT·원자료 등)는 외부 검증 대상에서 제외하되 "내부 자료로 분류" 명시.
- 각 인용을 "본문 주장 ↔ 인용 출처" 쌍으로 정리하고 번호를 매긴다.
- **번호 통일**: 1·2단계에 **같은 번호(①②③④)**, 본문 등장 위치는 별도 칸 표기.

---

## 1단계: 서지 실존/정확성

각 출처가 실제로 존재하고 서지정보(저자·연도·제목·발행처/학술지·권호·페이지·URL)가 맞는지 **웹 검색**으로 확인한다.

```
1. 웹검색·학술DB(KCI·DBpia·KoreaMed·Google Scholar)·공식DB(정부 보도자료·KOSIS 등)로 실존 확인
2. 출처 5등급 분류(아래)
3. 판정: PASS(실존·일치) / MISMATCH(존재하나 서지 불일치) / FAIL(존재하지 않음 = 환각 → 삭제·재검색)
```

| 등급 | 정의 | 사용 규칙 |
|------|------|-----------|
| T1 | 정부 공식 통계·법령·판례 | 핵심 주장 단독 근거 가능 |
| T2 | 국제기구·공공 연구기관 발간물 | 핵심 주장 단독 근거 가능 |
| T3 | 피어리뷰 학술논문, 국책연구 보고서 | 핵심 주장 단독 근거 가능 |
| T4 | 주요 언론, 검증된 NGO 보고서 | 보조 근거만 |
| T5 | 블로그·위키·SNS·출처 불명 | 사용 금지 |

## 2단계: 인용 적절성 (이 스킬의 핵심)

출처 **원문을 직접 읽고**, 본문 주장이 그 원문에 의해 실제로 뒷받침되는지 판정한다.

```
판정 3분류:
- 뒷받침됨   : 출처 원문이 본문 주장을 직접 지지
- 부분적     : 일부만 지지(과확장 / 대상·범위 어긋남 / 변수명·자료원 불일치 / 방향성만 맞음)
- 뒷받침 안됨: 출처가 그 주장을 다루지 않음(인용 부적절)
```

### 2-1. 원문 직접 판독 — 추측 금지 (필수)

제목·초록·검색 스니펫만 보고 판정하지 않는다. **반드시 원문 본문을 연다.** PDF는 샌드박스에서 PyMuPDF로 추출한다. 웹의 PDF는 `requests`로 받아 읽고, 정부 보도자료처럼 JS로 가려진 다운로드도 직접 받아낸다(`references/pdf-and-deeplink-retrieval.md` 참조).

### 2-2. 페이지·행 핀포인트 (의무)

"출처가 그렇게 말한다"로 끝내지 말고, **어느 페이지 몇 번째 줄**에 그 내용이 있는지 적고 원문 표현을 직접 인용한다.

```python
import fitz
d = fitz.open('source.pdf')
for i in range(d.page_count):
    for ln, line in enumerate(d[i].get_text().split('\n'), 1):
        if KEYWORD in line:
            print(f'p{i+1} l{ln}: {line.strip()}')
```

전수검색으로 **부재**도 증거가 된다(키워드 0회 → 과확장 판정 근거).

### 2-3. 자주 나오는 부적절 인용 패턴

- **과확장** / **변수명 오기**(가구소득↔처분가능소득) / **자료원 불일치**(소득 4분위↔의료급여·차상위) / **방향성만 맞음**.
  변수명·자료원은 반드시 1차 PDF로 확인한다(요약·언론은 표현을 바꾼다).

## 3단계: 독립 재검증 (CoVe) — 오판 방지

Cowork에는 별도 서브에이전트가 없으므로, **사전 결론을 보지 않는 독립적 재판단 패스**를 직접 수행한다.

```
- 1·2단계 판정을 일단 옆에 치워두고, "본문 문장 ↔ 출처" 원시 쌍만 다시 본다
- 출처 원문(PDF/공식 페이지)을 새로 열어 백지에서 재판정한다
- 1차 판정과 다르면 1차 출처 원문을 근거로 최종 판정한다
```

> **원문을 연 쪽이 항상 이긴다.** 요약·언론에 기댄 1차 판정이, PDF를 직접 연 재검증에 의해 뒤집히는 경우가 흔하다.

---

## 4단계: 부적합 인용에 대한 대체 출처 제시

'부분적'·'불일치'·'안됨' 판정 건은, **본문 주장을 실제로 뒷받침하는 더 적합한 출처를 웹 검색으로 찾아 제시**한다.

```
- 후보마다 [기관/저자, 연도, 제목, 실제 접속 URL, 등급, 뒷받침하는 구체 수치/문장]
- URL은 실검색으로 확인된 것만(환각 금지). 딥링크 없으면 해당 통계·지표의 실제 딥링크를 찾아 제시
```

---

## 5단계: 검증 리포트 산출 (다운로드 제공)

샌드박스에 파일로 만들어 다운로드 링크로 준다. 구성:

```
1. 검증 개요 (대상 문서·일자·도구·범위·출처 번호 ①~④)
2. 종합 판정 (서지 PASS/FAIL · 인용 뒷받침/부분/안됨 집계)
3. 1단계 서지 검증표 (+1차 URL·딥링크)
4. 2단계 인용 적절성 검증표 (본문 위치 + 출처 페이지·행 + 판정)
5. 수치 재검증 (합계·비율·단위)
6. 대체/보강 레퍼런스 (URL·등급·근거)
7. 사람 검토 필요 체크리스트
```

표기 규칙: 기관은 **현행 명칭+도메인 병기**(예: '성평등가족부(mogef.go.kr)'). 1·2단계 **동일 번호**.
임계: (FAIL+불일치) ÷ 전체 > 30%면 문서의 근거 전면 재작성을 권고.

> .docx 리포트를 원하면 `pip install python-docx`로 표 포함 문서를 생성해 다운로드 제공한다.

PDF/딥링크 취득 실전 기법은 `references/pdf-and-deeplink-retrieval.md` 참조.
