## 빠르게 하는 법 — 왕복을 줄이고 나눠서 돌린다

인용 30건짜리 문서를 검증하는 데 16분이 걸렸다. 그 시간을 뜯어보면 이렇다.

```
도구 실행      3초   (0.3%)
모델 사고·왕복 958초 (99.7%)   — 호출 31회 × 평균 31초
```

**도구를 빠르게 만들어도 소용없다.** 줄여야 할 것은 왕복 횟수이고, 나눠야 할 것은
인용마다 따로 하는 판단이다.

### 1. 기계로 찾을 것은 한 번에 찾는다

인용마다 `find` 하고 생각하고 또 `find` 하면, 찾는 데 0.1초 걸릴 일에 30초짜리 왕복이 붙는다.
찾을 수 있는 것을 먼저 다 찾아 놓고 판단만 이어서 한다.

```bash
python3 -m refver resolve citations.json --corpus <출처폴더> --document <원문서>
```

한 번에 돌려주는 것.

| 돌려주는 것 | 무엇에 쓰나 |
|---|---|
| 주장이 원문서에 축자로 있는가 | 요약해 옮긴 주장을 걸러낸다 |
| 인용한 출처가 코퍼스에 있는가 | 1단계 FAIL 후보 |
| 주장의 수치가 출처에 몇 번 나오는가 | 0회면 VALUE 불일치 후보 |
| 출처에서 단서가 겹치는 줄 | 근거 후보. 여기서 골라 쪽·행을 확정한다 |
| 주장에는 있는데 출처에 없는 낱말 | 부재 증거 후보 |
| 같은 수치가 다른 출처에도 있는가 | 자료원 불일치·2차 출처 인용 후보 |

이건 **후보**다. 어느 줄이 진짜 근거인지, 그 수치가 같은 것을 가리키는지는 읽고 판단해야
한다. 예컨대 "24.1이 출처에 1회 나온다"는 결과가 나와도, 그게 탄소가격이 아니라 원자력
비중일 수 있다.

검색을 더 해야 하면 그것도 묶는다.

```bash
python3 -m refver lookup queries.json --corpus <출처폴더>
# [{"source_id":"E01","quote":"확인할 문장"}, {"source_id":"E03","terms":["전기요금","요금"]}]
```

### 2. 인용 판단은 나눠서 동시에 돌린다

인용 하나를 판단하는 일은 다른 인용과 무관하다. 독립 에이전트를 띄울 수 있으면
묶음으로 나눠 동시에 돌린다. 30건을 5건씩 여섯 묶음으로 나누면 벽시계 시간이 크게 준다.

각 묶음 에이전트에 주는 것.

- 그 묶음의 인용과 `resolve` 결과
- **출처 목록 전체와 코퍼스 경로** — 자기 묶음 밖 출처를 확인해야 하는 경우가 있다.
  2차 출처가 1차를 잘못 옮긴 경우가 대표적이다
- 슬롯 표와 판정 규칙표

각 묶음이 돌려주는 것: 인용별 슬롯 표, 판정, 근거(출처·쪽·인용문), 판단 근거 메모.

**나누면 안 되는 것.**

- **최종 리포트 조립** — 한 곳에서 한다. 묶음마다 리포트를 쓰면 번호와 형식이 어긋난다.
- **독립 재검증(3단계)** — 이건 병렬화가 아니라 격리가 목적이다. 앞선 판정을 보지 못하는
  상태를 만드는 것이 핵심이므로, 판단한 에이전트와 다른 에이전트가 해야 한다.
- **문서 전체를 봐야 아는 판단** — 같은 출처를 여러 인용이 쓰는데 한 곳에서만 단서를
  떼어 냈다든지, 출처가 자기모순이라든지. 조립 단계에서 한 번 더 훑는다.

### 3. 순서

```
0단계 인용 수집        한 번에 (문서 판독 1회)
   ↓
resolve               한 번에 (기계 조회 전부)
   ↓
1·2단계 판단           묶음으로 나눠 동시에
   ↓
3단계 독립 재검증       문제 판정 건만, 별도 에이전트가 눈감고
   ↓
조립·기계 점검·리포트   한 곳에서
```

에이전트를 띄울 수 없는 환경이라면 나누는 단계만 순차로 하면 된다. 왕복을 줄이는 1번은
어디서나 그대로 쓴다.
